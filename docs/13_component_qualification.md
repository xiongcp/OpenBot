# 组件验证与接入门禁

## 资格验证的目标

候选库能够导入、示例能运行、上游有测试，都不能证明它符合OpenBot的授权、隔离与恢复合同。本章将复用风险转成独立可复查的验证项目。实际结果写入templates/component-qualification.md对应记录和evidence目录；本设计交付中的所有真实组件验证状态为NOT_RUN。

新库接入按“候选登记、来源与许可、精确锁定、副作用观察、合同/故障、目标平台、发布资产”推进。任一强制项失败，相关能力不可启用；可继续其他不依赖它的任务。组件变更只重新运行受影响门禁和固定回归，避免每次微小改动都重跑全部平台。

## 必须记录的证据

| 证据组 | 必须包含 |
|---|---|
| 身份 | package/repository、精确版本或commit、下载来源、sha256、可选特性和传递依赖 |
| 环境 | OS/架构、Python/Rust/SDK版本、容器引擎与配置、浏览器/grammar/词表版本 |
| 行为 | 实际网络请求、DNS、子进程、读写路径、线程、初始化时延、关闭和取消表现 |
| 合同 | 输入/输出、流式分片、错误码、超时、重试次数、预算与结果未知处理 |
| 许可 | LICENSE/NOTICE来源、选用的许可分支、分发方式、未决问题 |
| 结果 | 测试命令、退出码、脱敏日志、预期与实际、限制、责任人和关联任务 |
| 升级 | 触发复验的变化、回退版本与资产、上游补丁退出条件 |

源码浏览只能证明文档或实现的可见行为，不能把它记成真实OS或真实租户通过。所有证据带日期与版本；历史issue只证明曾出现该问题，需要针对选定版本确认是否仍存在。

Q01的“没有观察到网络”必须明确观察范围。仅mock httpx不能拦住requests、Rust扩展、子进程、DNS或浏览器；使用目标平台可提供的网络隔离/审计组合，并分别报告已覆盖和未覆盖部分。离线模式限制的是OpenBot进程与其受管执行域，不声称改变整台用户电脑的联网状态。

Q02使用经过核实的RFC向量与所选库；不在测试代码中再写一个同样错误的排序器当oracle。Python是binding_hash的权威，UI无需独立实现授权判定；只有实际引入另一种语言的JCS实现时才要求跨实现字节一致。入口先拒绝重复键，再进入普通dict，不能让解析器静默保留最后一个键后才校验。

Q04区分模型请求和工具动作。Provider请求可能重复计费，但不得造成工具自动重复执行。预算状态未知保守保留；应用重试、SDK重试与HTTP transport重试必须可数且只有一个策略负责人。

Q08/Q09必须分别证明本机客户端、Worker、容器和子孙进程的最终状态。host端Docker控制接口属于受信适配器，不传入不可信容器。产物导出在停止并wait后进行，校验完成再remove；恢复器处理尚未删除的受管容器，不能删除未登记的用户容器。

Q10不把一次issue中的24.27秒导入作为所有机器的预算。测量至少区分解释器启动、SDK导入、凭据检查、端点发现、握手和业务ready。健康监控位于可能阻塞组件之外；重建前确认旧实例退出，避免两个Gateway竞争收件。

Q13的通过标准是已定义规则与canary集合的完整通过，不是“识别世界上全部秘密”。不确定的敏感内容不通过扫描器的阴性结果自动降级；SECRET和SENSITIVE仍受分类策略控制。不得将真实凭据作为第三方在线验证输入。

## 最小协议PoC与正式垂直切片

先在M0完成小范围协议PoC：只验证持久化、JCS绑定、批准、claim、派发前检查、崩溃点与UNKNOWN资源隔离。使用FakeProvider和MockWorker，无需真实飞书、浏览器或容器。通过后才适合大规模并行开发。

OB-029仍代表M1集成后的正式垂直切片，必须使用真正的本地API、权限、产物和隔离执行路径。M0的PoC不能把OB-029或真实安全工具任务提前标为DONE。两个里程碑的证据分开保存，既尽早降低架构风险，也避免mock掩盖真实集成问题。

## 性能、收益与工期

本轮不采用U3的Stars、固定行数、10倍速度、20至100倍提升或百分比复用收益作为验收值。实施时分别测量冷启动、ready时间、常驻内存、安装体积、一次受控工具动作、恢复耗时和回调分位数，记录硬件、版本、样本数与测量方法。

开源复用节省的主要是协议解析和成熟原语实现；适配、隔离、供应链、真实平台验证和上游维护仍是工作量。M0按准入证据完成情况重新估算剩余任务，S/M/L仅表示相对规模，不把新增任务数直接折算为日历天数。

## 变更后的复验规则

纯文档改动只检查引用与任务一致性；适配器配置变化重跑对应Q项；SDK主版本、解析/哈希行为、完整工具定义、隔离引擎或浏览器build变化重跑相关合同、恢复和平台门禁。涉及不可变提案语义的变化使旧授权失效，不能重算旧hash后继续执行。

每次升级保存原锁文件、构建资产和兼容范围。出现版本冲突或已知漏洞时可禁用受影响能力并继续其他能力；不以忽略错误、放宽网络或回退宿主的方式保持“可用”。
