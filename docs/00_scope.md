# OpenBot 产品范围与工程基线

版本 1.2 · 2026 年 11 月 4 日 · 状态为建议实施基线

## 本次结论

保留前两份材料已经形成的方向：Python 薄内核、自有任务与策略模型、飞书优先、SQLite 本地持久化、Tauri 作为桌面入口、执行器和模型可替换。v1.2根据新增的27页组件复用评估，明确默认组件、条件候选、源码参考与暂缓项，增加组件准入、离线资产、SDK副作用和平台资格验证。工程设计包不是已经实现的 OpenBot 应用；其中 SQL、JSON Schema、接口定义和任务依赖经过静态或离线验证，真实飞书、真实模型和三平台安装仍须由后续任务验证。

设计版本1.2不等于所有通信协议都升级为1.2。本轮保留23张数据库表、14个本地API操作和原有授权/恢复协议；组件清单、验证模板及任务计划独立版本化。实际接口变化仍须独立合同迁移，不能全仓替换版本号。

最先开发的产品是一个由用户控制的本地常驻助手：在指定工作区检索资料、解释代码、生成补丁、经授权执行隔离测试，并通过飞书或本地 CLI 查看进度、确认动作、取消和恢复任务。明确区分三个交付层级：本地闭环原型、符合原研究稿能力范围的 MVP、具备桌面安装与诊断体验的 Beta。

## 输入与证据边界

输入 U1 是《OpenBot 开源桌面智能体深度研究报告》，共 20 页；U2 是《OpenBot 架构设计与任务规划》，共 36 页。页码使用 PDF 物理页码。U1 第 14 页列出单用户 daemon、至少两个 Provider、文件 Shell Browser MCP、飞书与三平台 CLI 等 MVP 能力；本方案通过分阶段门禁保留这些目标，不把桌面 Computer Use 提前为 MVP 必选项。

未提供源码仓库、已完成清单、锁定依赖、目标飞书租户或性能实测。因此所有任务初始状态为 TODO；原材料中的工期、Stars、精确冷启动耗时、成功率和竞争产品结论不作为实现验收依据。标为“建议”“目标”“默认”的值都是本次设计决定，不能对外当作已经测得的产品能力。

## 默认假设

| 编号 | 本方案采用的默认值 | 对实现的影响 |
|---|---|---|
| A01 | 一个 OS 用户、一个 OpenBot profile、一个 owner、一台执行设备 | 本地配置与身份隔离；不做企业多租户 |
| A02 | 一个自建飞书应用只连接一个活动 gateway | 消除竞争消费导致的设备路由丢失 |
| A03 | 先交付 CLI 和飞书；Tauri 在内核门禁通过后接入 | UI 不成为运行时的依赖 |
| A04 | 三平台核心协议从第一天 CI；真实打包按平台分别验收 | 不用 WSL 代替 Windows 原生测试 |
| A05 | 试点打包优先 macOS ARM64，Windows x64 与 Linux x64 随后；实际主机不匹配时通过 ADR 调整 | 这是默认排程，不是已经确认的用户环境要求 |
| A06 | 用户自备模型凭据与飞书自建应用；模型费用直接归用户账户 | 无中央收费与模型代理服务 |
| A07 | 远程执行代码需要可用的隔离后端；没有后端则拒绝该能力 | 不静默降级为宿主机任意命令 |
| A08 | 初期不承诺唤醒休眠或关机电脑 | 网络重连恢复与远程硬件唤醒是不同能力 |
| A09 | 生成补丁默认放在独立工作树或暂存区；应用到用户原目录需要明确动作 | 不覆盖既有未提交修改 |
| A10 | 所有架构建议均可由 ADR 修改，但变更必须同步合同、任务和验收 | 避免两个编码助手形成相互矛盾的实现 |

## 目标用户与关键场景

S01 代码诊断：用户在飞书指定工作区和问题，助手读取允许范围内的文件，生成带来源路径的诊断及补丁草稿，不自动提交或推送 Git。

S02 隔离验证：用户审阅将运行的 argv、代码快照和网络权限，批准后在隔离环境运行测试；输出保存为有体积上限的 artifact，卡片展示摘要。

S03 长任务恢复：用户隔数小时审批，期间 daemon 重启。系统恢复已经持久化的任务；对结果不明的外部动作进入核对流程，而不是自动重发。

S04 取消与接管：用户从任一已授权入口取消任务，阻止后续动作；对于已经发生的修改或消息发送明确展示实际结果，不显示虚假的“已撤销”。

S05 浏览器查阅：使用 OpenBot 专用浏览器配置读取获准域名；浏览器页面内容视为外部输入。网页提交、文件上传、购买或向第三方发消息必须绑定具体动作审批。

S06 离线工作：OFFLINE 模式仅允许本地模型、工作区和本地工具；飞书和网络浏览器处于禁用状态。LOCAL_MODEL 模式仅限制模型出口，仍可按单独授权连接飞书。

## 交付范围

| 层级 | 包含 | 完成标志 |
|---|---|---|
| M0 设计与风险验证 | 仓库骨架、合同、威胁模型、飞书 SDK 与进程监督 spike | 无未解决的 P0 架构问题 |
| M1 本地闭环原型 | CLI、持久化、一个 Provider、文件 ACI、审批与恢复、隔离进程 | 断网可用 mock 演示；安全边界测试通过 |
| M2 远程闭环 | 飞书配对、消息去重、审批、Outbox、断连恢复 | 测试租户完成真实端到端任务 |
| M3 产品 MVP | 至少两个 Provider、受控 Browser/MCP、三平台 CLI、评测与备份 | 原 U1 MVP 范围有明确能力报告 |
| M4 桌面 Beta | Tauri、签名安装、升级回滚、诊断与操作面板 | 干净机器安装和升级恢复通过 |
| 后续 | GUI 控制、定时任务、更多渠道、多设备、企业策略 | 独立 ADR 与任务，不阻塞前述交付 |

三平台一致指合同、行为和错误码一致，不代表所有 OS 原生能力相同。macOS/Windows 的隔离代码执行可以依赖 Linux 容器后端，但这不等于支持原生 PowerShell、Win32 或 macOS 自动化。能力探测必须把这种差异显示给用户。

## 非功能目标

| 领域 | 初始目标 | 测量条件或边界 |
|---|---|---|
| 飞书回调 | 协议要求 3 秒内响应；内部处理目标 p99 小于 1 秒 | 测试租户、稳定网络、1000 次回调；不得把目标写成官方保证 [S01] |
| 持久化 | 收到成功提交确认的任务可在进程崩溃后查询 | WAL 加 FULL；断电还受 OS 与存储实际持久化能力影响 [S03] |
| 动作安全 | 未授权动作执行数为零 | 指指定测试集及路径，不宣称“绝对安全” |
| 恢复 | 进入确定状态或待核对状态；不重复执行非幂等动作 | 在所有规定崩溃点注入故障 |
| 预算 | 每个任务具备步骤、调用、时间与费用上限 | 费用按 provider 返回使用量或估算标记记录 |
| 资源 | 单 profile 默认一个活动任务、一个浏览器动作、一个写工作区任务 | 先串行，后续再扩展锁调度 |
| 可用性 | daemon、gateway、executor 的健康分别可见 | UI 已连接不等于远端与执行器健康 |
| 隐私 | 凭据不进入模型上下文、普通日志与默认诊断包 | 以合成 canary secrets 验证，而非只依赖正则替换 |

代码量只用来观察复杂度，不设置 5000 到 15000 行的硬交付门槛。把安全、恢复和合同测试挤出所谓薄内核，会让代码看起来短而让行为不可控。
