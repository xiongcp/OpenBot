# 遗漏项与原方案修订

## 审阅方法

以下区分“原文缺失”“提到但未闭环”和“建议修正”。保留原方案已经有效的部分，重点补全执行、持久化、身份、平台和交付的边界。U2 已覆盖审批、WAL、进程清理、MCP pinning 等概念；不能把这些重复列成全新发现。

## 避免把证据写成保证

U2 中“24.27 秒冷启动”“首次连接 100% 失败”“重连必定 30 秒内”“一秒内所有子孙进程消失”“稳定性百分比”等描述，缺少在目标版本、机器和负载上的复现实验，不能进入本项目的能力承诺。将它们替换为版本化测试场景和可测量的目标。

macOS TCC 提示周期、SDK 内部方法名和第三方权限插件支持范围都是随版本变化的细节。开发时通过 capability probe 与真实机器测试确认；不要把“某个系统版本必定每30天提示”写死为核心逻辑。

“模型输出带污点”是来源追踪，不是注入已经被清除的证明；“用户点击批准”是对特定动作授权，不是对整个会话全部后续行为的授权；“日志可回放”是观察历史，不是再次执行外部副作用。
