# M1 首条持久化垂直切片演示与验收说明 / M1 First Persistent Vertical Slice Demo & Verification (OB-029)

## 中文说明

### 1. 演示范围与设计边界（OB-091 vs OB-029）
- **OB-091（M0 早期协议 PoC）**：仅在 `tests/protocol/` 中用 MockWorker 验证 8 个崩溃点与 23 表 CAS/触发器语义，不接入认证本地 API、CLI、真实工作区补丁或受控子进程。
- **OB-029（M1 首条持久化垂直切片）**：通过 `services/core/src/openbot/application/vertical_slice.py`（`M1VerticalSliceHarness`）与 `tests/integration/scenarios/first_vertical_slice/test_first_vertical_slice.py`，将 **CLI (`openbot.cli`) → 认证本地控制 API (`LocalControlApiServer`) → 持久 Task (`Inbox`/`TaskStateService`) → 离线提案 (`OperationService`) → 六维策略与审批 (`ApprovalService` + 一次性 challenge nonce) → 两次短事务派发 (`DispatchService`) → 真实本地受限文件补丁 (`WorkspacePatchTool`) / Artifact 存储 (`ArtifactStore`) / 进程树监管回收 (`ProcessSupervisorService`) → 持久 Outbox (`OutboxService`)** 闭环串联。
- **严格离线与诚实声明**：默认运行于 `OFFLINE` 模式与合成数据，**绝不调用真实生产云模型或真实飞书服务**；本地受限文件/进程效果与 fault executor 崩溃注入计数分别独立统计，不将本地 FakeProvider 通过宣称为真实飞书或真实云模型已验证。

### 2. 五个崩溃点与重复输入验证
1. `before_claim`：审批通过（`READY`）后、首次 `claim` 前发生 runtime epoch 切换（`ep_1 -> ep_2`），未发生任何外部副作用（`fault_executor_effect_count = 0`），新 epoch 正常接管完成。
2. `after_claim_before_dispatch`：首次 `claim` 消费 `APPROVED -> CONSUMED` 后、第二短事务 `begin_dispatch` 前崩溃重启；原 `CONSUMED` 绝不复活，由 `RecoveryService.recover_operation` 复验原授权未过期/未漂移后签发一次性 `RecoveryTicket` 完成 Attempt 2 派发（崩溃前副作用计数 `0`，盲目重放计数 `0`）。
3. `after_dispatch_before_effect`：进入 `DISPATCHING` 后崩溃重启，自动转入 `UNKNOWN` 与 Task `RECONCILING` 并冻结资源租约（quarantine）；经 CLI `operation reconcile` 上传内联核对证据并执行 `task resume` 恢复。
4. `after_effect_before_receipt`：外部动作已执行一次（`fault_executor_effect_count = 1`），但在本地写入完成回执前崩溃；恢复器严禁自动重放 `RECONCILE_ONLY` 副作用（`blind_replay_count = 0`），经 CLI 提交核对证据后转 `SUCCEEDED`。
5. `after_complete_before_outbox_ack`：业务操作已完成且通知已入队 `outbox`，在投递确认前发生 epoch 切换；新 epoch 仅继续投递 `outbox` 消息，绝不重新执行业务操作。

### 3. 可复现验证命令
- `PYTHONPATH=services/core/src .venv-m1/bin/python -m pytest tests/integration/scenarios/first_vertical_slice/test_first_vertical_slice.py -q`（6 passed）

## English Summary

### 1. Scope & Boundary (OB-091 vs OB-029)
- **OB-091 (M0 Protocol PoC)**: Verified crash-recovery state transitions in `tests/protocol/` using MockWorker without the authenticated local HTTP API, CLI, real workspace file patching, or supervised worker processes.
- **OB-029 (M1 First Persistent Vertical Slice)**: Connects **CLI (`openbot.cli`) → Authenticated Local Control API (`LocalControlApiServer`) → Persistent Task (`Inbox`/`TaskStateService`) → Offline Proposal (`OperationService`) → 6D Policy & Approval (`ApprovalService` with one-time challenge nonce) → Two-Transaction Dispatch (`DispatchService`) → Real Restricted Workspace File Patch (`WorkspacePatchTool`) / Artifact Store (`ArtifactStore`) / Supervised Worker Reclaim (`ProcessSupervisorService`) → Durable Outbox (`OutboxService`)** in `services/core/src/openbot/application/vertical_slice.py`.
- **Offline & Honest Boundary**: Runs strictly in `OFFLINE` mode with synthetic data (`real_production_services_called = False`). Real local file/process effects and fault-executor crash counts are tracked separately without claiming real Feishu or production cloud model qualification.

### 2. Five Crash Points & Duplicate Input Verification
Covers `before_claim`, `after_claim_before_dispatch` (recovering via one-time `RecoveryTicket` without reviving `CONSUMED`), `after_dispatch_before_effect`, `after_effect_before_receipt` (entering `UNKNOWN`/`RECONCILING` with zero blind replay, resolved via CLI `operation reconcile` and `task resume`), and `after_complete_before_outbox_ack`, plus idempotent duplicate CLI `task create` requests.

### 3. Reproducible Command
- `PYTHONPATH=services/core/src .venv-m1/bin/python -m pytest tests/integration/scenarios/first_vertical_slice/test_first_vertical_slice.py -q` (`6 passed`)
