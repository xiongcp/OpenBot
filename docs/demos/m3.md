# M2 飞书受控端到端验收说明与 M3 准入边界 / M2 Feishu Controlled End-to-End Verification & M3 Entry Boundary (OB-056)

## 中文说明

### 1. 受控端到端主流程与 6 个故障场景（`FeishuM2EndToEndHarness`）
`services/feishu_gateway/src/openbot_feishu/e2e_harness.py` 与 `tests/integration/feishu/test_feishu_e2e_harness.py` 将 M2 飞书适配全链路闭环串联：
- **主流程**：本地生成短 TTL 配对挑战 → 远端 claim 生成待确认候选 → 本地显式确认激活 owner → 飞书 WebSocket 入站消息经 `Inbox` 持久化提交后返回 `ws_ack=True` → 生成脱敏普通审批卡 → 飞书 `card.action.trigger` 回调校验真实 `operator.open_id` 与一次性 nonce 并通过 CAS 将 Operation 置为 `READY`。
- **6 个必测故障与攻击场景**：
  1. `disconnect_and_jittered_reconnect`：网关断线后经外部监督器确认旧实例退出并重连。
  2. `daemon_restart_recovery`：daemon 发生 runtime epoch 切换（`ep_1 -> ep_2`）后恢复。
  3. `duplicate_approval_callback`：重复点击审批按钮被安全拦截，不发生二次唤醒。
  4. `stale_card_on_cancelled_task`：任务取消后点击旧审批卡返回 `APPROVAL_REJECTED_OR_STALE`。
  5. `revoked_owner_rejected`：撤销 owner 后递增 `identity_epoch`，原 `open_id` 立即失效。
  6. `dual_consumer_spawn_blocked`：旧消费者未确认退出前拒绝启动第二消费者。

### 2. 真实租户诚实边界声明
- **真实飞书服务端协议与长连接握手已实测（`OB-047`）**：已对 `https://open.feishu.cn` 与 `wss://msg-frontier.feishu.cn` 完成真实 `tenant_access_token`（`147.88 ms`）、`bot/v3/info`（`169.04 ms`）、WebSocket 端点发现（`102.11 ms`）与 TLS `101 Switching Protocols` 握手（`208.38 ms`）、`im/v1/chats` 只读列表（`314.48 ms`）以及 `cardkit/v1/cards` 卡片实体创建/更新与乱序拒绝（`code=300317`）实测。
- **手机端真人点击诚实边界**：由于自动化回归期间无真人在手机客户端点击卡片触发实时 `card.action.trigger` 回调，报告仍保持 `real_feishu_tenant_verified = False`（不把无真人手机点击的自动化回归冒充为完整手机端真人交互验收）与 `claims_full_mvp_complete = False`。

`services/feishu_gateway/src/openbot_feishu/e2e_harness.py` and `tests/integration/feishu/test_feishu_e2e_harness.py` verify the complete M2 Feishu workflow (local pairing challenge & confirmation → WebSocket persist-before-ACK inbound task creation → plain approval card rendering → authenticated `card.action.trigger` CAS callback) plus 6 failure scenarios (`disconnect_and_jittered_reconnect`, `daemon_restart_recovery`, `duplicate_approval_callback`, `stale_card_on_cancelled_task`, `revoked_owner_rejected`, `dual_consumer_spawn_blocked`).
