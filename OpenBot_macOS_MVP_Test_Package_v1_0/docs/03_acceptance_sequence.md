# 严格MVP验收的执行顺序

## E0：冻结基线与验收真实性

交付source_sha、环境/架构、profile与工作区范围、实际依赖组、命令表、用例清单、外部服务范围和私有证据目录。检查每个“verified”字段的产生方式：是实际观测、模拟合同还是调用方声明。将模拟测试保留在适当层，不直接累计为真实能力。

先处理MVP-001至005的基础CI问题，以及MVP-008/009/012/014的证据问题。独立根因可逐项提交；前项已成功推送但CI因已知基础故障尚未验证，保留CI_BLOCKED并继续下一根因。关键门禁不得以尚未提供证据的手写true通过。

退出条件：测试能正确收集，失败/超时/缺环境不会产生本轮PASS，报告可绑定实际候选SHA。若仍有产品入口缺失，G0可完成但G2继续阻塞。

## E1：工程与受控组件回归

执行类型、格式、合同、SQLite、各模块回归；另外安装并运行明确要求的SDK组。记录collected/passed/failed/skipped/xfail数量和各skip原因；至少一次在干净环境执行相同命令。发现导入或收集错误先修，不能把少收集测试后的绿灯作为改进。

重点断言：JSON重复键与JCS向量；批准后规范字节不变；writer取消后查询真实提交结果；状态、审计、Outbox事务一致；secret_ref与真实秘密分离；SDK实际请求数和预算；路径、补丁、Artifact完整性。

退出条件：本范围所有必需用例PASS，collect错误0，未说明的skip/xfail为0；测试结果明确标为受控环境，真实服务部分另记。

## E2：真实进程入口和第一条产品闭环

这是最先应当能演示的功能，不依赖Tauri。所有用户操作经已安装console脚本/真实本地API，产品进程由正式入口启动；不得注入_in_process transport、直接SQL写成功或从测试进程调用核心函数代替用户流程。

准备合成工作区：hello.py含一个可检查的小错误，test_hello.py定义正确结果，notes.txt先制造一项用户未提交改动。另建工作区外的canary文件及指向它的symlink，作为拒绝访问反例。任务仅授权修复hello.py和运行受限测试，不授权读取canary、改notes.txt、执行网络动作或推送该合成仓库。

执行步骤：

1. 启动独立测试profile的真实daemon，确认监听、认证、PID和profile归属。
2. 用console创建任务，记录task_id和入站幂等键；重复同一请求，逻辑Task不增加。
3. 用户侧只获取经数据分类过滤的ApprovalPreview，核对允许展示的目标路径、旧/新内容hash、动作、有效期和影响范围。内部ToolProposal的规范字节及binding hash由受保护的测试观察器核验，不向客户端返回原件或SECRET。需要本地审阅时遵守LOCAL_REQUIRED，本地也不得展示SECRET；预览不足以说明影响时不得远程批准。
4. 在批准前核对hello.py未改动、没有测试进程、没有模型或工具越权出口。
5. 为文件补丁与受限测试分别建立具体Operation，各自按policy获得并消费独立授权。先观察补丁的claim、DISPATCHING、实际修改与receipt，再基于新工作区快照生成受限测试命令并按其策略审批；不得让两个工具共享一次grant或dispatch。对同一审批重复提交相同决定不能重复执行。
6. 检查测试结果、hello.py内容和Artifact摘要；notes.txt及工作区外canary保持原样。
7. 通过产品查询最终状态；确认SUCCEEDED由有效结果产生，不能仅由harness写入。
8. 停止并重新启动产品，从同一profile重新查询，Task/Operation/Approval/Attempt及产物关联保持。

退出条件：真实入口、真实隔离路径和实际产物可相互核对。FakeProvider可用于前期确定性切片，但Mac MVP的两Provider与真实任务质量仍须在G5补齐。

## E3：授权、并发、故障与恢复

为每个动作同时记录request_count与effect_count。故障控制器、服务端效果账本和用户证据应独立于被终止的进程。使用测试构建中的受控屏障，在明确事务事件到达后注入故障；不要用随机sleep猜测是否正好处于竞态窗口。

| 注入点 | 控制器动作 | 恢复必须满足 |
|---|---|---|
| claim之前 | 停止或终止daemon | 未消费授权、未派发，按当前有效条件决定能否继续 |
| claim已提交、DISPATCHING之前 | 终止旧实例并确认旧执行域失效 | 审批保持已消费；依恢复票据与原条件安全处理，不恢复审批可用状态 |
| DISPATCHING已提交、真正发包之前 | 终止daemon | 持久状态不能单凭测试控制器“知道没发包”就证明产品也知道；没有可靠证据时保持UNKNOWN并核对 |
| 外部效果完成、本地回执之前 | 服务端记账后断连或杀进程 | 效果恰好一次，不自动重发；状态UNKNOWN/RECONCILING，查询或独立证据可核对 |
| 回执与状态已提交、用户反馈之前 | 终止daemon/反馈通道 | 原动作不重做；只恢复待发送反馈/Outbox，旧revision不覆盖新状态 |
| 磁盘满或writer超时 | 在专用受限卷/注入点制造失败 | 派发前持久化失败则不执行；已发生效果后持久化失败则不能声称未执行 |

并发测试采用同一PENDING/version的20个批准/拒绝竞争，互斥决定最多一个成功；批准后的合法撤销是后续版本操作，不受这个“最多一个”限制。另测取消先于claim、取消在claim与dispatch之间、取消晚于实际效果三种确定性顺序。

至少验证：过期审批、篡改argv/文件hash/收件人、owner撤销、旧epoch与旧worker、资源generation变化、UNKNOWN状态下换新Task/Operation ID、非幂等动作成功后断连。任何未授权效果、危险重复效果、错误成功声明均阻塞发布。

## E4：macOS真实系统边界

在同一候选上执行Mac原生用例：用户级daemon、同profile双实例、Keychain、路径与symlink、子进程及容器生命周期、真实休眠唤醒、网络切换、重新登录/重启、首次离线使用。

不要为了验收先授予所有系统权限。CLI/飞书/Headless Browser所需权限与后续GUI自动化的Accessibility/Screen Recording分开；未实现GUI的MVP不能靠授予屏幕权限掩盖缺少正式入口。真实Keychain权限弹窗可能需要本机用户操作，记录必要的一次人工步骤，其他就绪测试继续进行。

Docker/Chromium后端资格必须绑定实际组合。Mac上的Linux VM能证明该VM内后端行为，不能替代macOS登录会话、原生文件/凭据语义或Linux x64发行资格。

退出条件：无未归属残留worker/容器，旧实例无法继续派发；权限与服务缺失能明确拒绝；所有原生通过记录来自OS或engine实际观测。

## E5：真实外部服务闭环

### 飞书完整任务流程

使用专用测试应用、已确认的测试会话与合成数据。API成功、CardKit序列校验和WebSocket101握手是各自有效探针，但完整流程还需以下步骤：用户发消息；真实长连接收到事件；Inbox去重；创建Task；展示审批；正确owner点击；真实Broker执行；Artifact/效果产生；Outbox反馈；重启后查询一致。

依次注入重复event_id、相同ID不同payload、同一卡片重复点击、错误owner、批准后重启、token过期、429、反馈乱序、网络断开与连接恢复。所有会话写操作都限定配置的测试收件范围，不能用真实生产群作为默认测试目标。

### 云模型与Ollama

先对SDK做受控HTTP测试，再用明确预算的测试模型请求验证真实服务。记录模型ID、实际usage、请求ID、调用次数、超时与费用估算来源；禁止用模型说“执行了”代替工具效果。

Ollama采用已锁定的本地模型与已预置资产，核验禁云配置和实际出口。禁云设置不等于整个桌面应用所有后台流量已关闭；OFFLINE资格必须观测相应服务/进程树，缺模型或资产时不可静默下载或云回退。

### Browser与MCP

Browser使用受控网页，覆盖结构化读取、写前审批、导航/重定向/iframe/Service Worker/下载/弹窗、崩溃后的效果核对。实际DOM或服务端记录验证点击/提交效果，不以截图或action返回成功为唯一证据。

MCP启动已固定来源的真实stdio server，完成initialize/initialized与工具发现。覆盖工具定义变化、越权server、输出洪泛、成功后断连、非幂等重放阻止和server回收。只比较协议版本字符串不算握手通过。

## E6：恢复、长期运行和安装资产

备份演练至少包括空profile恢复、缺Artifact、秘密值不在备份中、secret_ref重新绑定、备份期间GC保护和恢复后UNKNOWN不被清空。破坏性注入只作用于本轮临时数据与配额卷，不对用户真实库做实验。

建议按三档运行：30分钟健康冒烟；2小时有界故障轮转；一晚8至12小时候选浸泡。时长是本轮建议计划，不是长期稳定性保证。记录负载、错误率、队列长度、内存趋势、模型预算、人工核对次数与实际故障事件，不把循环次数固定值当样本数。睡眠测试时不能用caffeinate阻止被测睡眠；一般浸泡与真实睡眠场景分开。

首次离线安装/启动必须在独立环境使用准备好的发行资产，不能借用开发机缓存的浏览器、grammar、tokenizer或镜像。需要签名分发时保持下载文件隔离属性，验证签名、公证及Gatekeeper正常行为；不要通过删除隔离属性或关闭系统检查获得通过。

## E7：最终候选和发布决定

所有必需证据绑定同一个verified_on_sha、tree/lock与发行资产hash；环境或依赖变化后重跑受影响门禁。每个修复记录introduced_by_sha以及最终验证它的候选SHA，确认包含关系。最后检查Git远端分支和对应CI，而非只看本地HEAD。

Mac MVP内测放行要求：本范围所有必需用例PASS；未解决S0/S1为0；未经授权副作用/危险重复效果/秘密canary外泄为0；UNKNOWN可核对；备份恢复可演示；真实服务和原生证据齐全。Windows/Linux和M4未完成项保留为范围限制，不能被整体M3通过结论覆盖。
