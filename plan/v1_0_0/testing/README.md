# 如何使用116项测试设计

`test_cases.json` 保留旧100项语义操作卡并新增16项；全部NOT_RUN。旧测试设计的review SHA保留为来源，本轮实际候选单独记录。

1. 先从当前parser/help/workflow绑定真实命令，不照抄不存在的命令。
2. 冻结平台、功能、模型、后端与手工/自动更新范围，再判定条件用例适用性。
3. 逐项执行，区分mock/真实进程/原生OS/真实外部服务；记录原始证据和脱敏摘要。
4. 缺环境的必需项BLOCKED，不用pytest skip或NOT_APPLICABLE掩盖。
5. 产品缺陷一个问题一次commit/push；最终累计候选重新核对相关证据。

`gates.json`将全部116用例映射到八个汇总门禁；同一用例可能支撑多个门禁。包自身的JSON/DAG检查不执行产品测试。
