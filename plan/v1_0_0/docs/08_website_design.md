# 官网信息架构、内容与视觉设计

## 当前核对与目标

仓库元数据未关联 homepage，has_pages=false；已读树未发现现成官网工程。本次无法据此排除别处已有网站，执行前应核对你实际控制的域名和部署项目。[R07]

官网要帮助访客依次完成理解、判断适用、安装、跑通首个任务和解决问题。开发阶段以源码验证/路线图为主要入口；正式版本通过后才展示真实下载按钮。所有界面图、性能、平台和安全描述都应能追溯证据。

## 建议技术路线

新增独立 `apps/website`：Astro 静态官网加 Starlight 文档，中英 Markdown/MDX，构建时读取经校验的 release/capability manifest。桌面端仍维持 Tauri + 静态前端，不为官网改变运行时。Starlight 已提供多语言路由与翻译回退机制，可减少自己维护文档导航和语言切换的工作。[W11]

网站不需要第二个业务后端、账号系统或数据库。发布到实际可用的静态托管；若采用 GitHub Pages，明确 project base path、资源 URL 与自定义域名配置。仅在域名归属和 DNS 验证后添加 canonical/homepage。每个 PR 可生成预览，生产发布保持独立步骤。

## 首页的七个区块

1. **首屏**：标题“让 AI 任务有权限边界，也有可核对的结果。”；副标题明确 macOS 优先和当前阶段；双 CTA。
2. **真实演示**：一段短视频或三张连续截图，展示目标→批准→结果。尚未实现则用带设计标签的线框。
3. **三个场景**：读取工作区资料、审查后修改文件、从飞书跟踪任务；每项有准确能力状态。
4. **工作方式**：输入目标、审批具体动作、查看产物/事实、遇到未知结果先核对；解释对用户的价值。
5. **支持与边界**：系统、模型、工具、联网模式及安装前置条件；未验证项清晰可见。
6. **开始使用**：当前源码验证；正式版则版本/架构识别后的下载与手动选择。
7. **底部**：文档、GitHub、路线图、变更、安全、许可、隐私和语言切换。

当前 CTA：“查看开发进展”“从源码验证”。v1.0.0 后 CTA：“下载 macOS 版”“完成第一个任务”。首屏不得把规划截图标成“产品实录”。

## 视觉规范建议

使用清爽的文档型界面：深蓝正文、青绿色主动作、大面积浅色背景，少量阴影。主色只承担操作/链接含义，绿色成功与青色品牌色分开。代码/证据区域使用等宽字体；中文正文优先系统字体，避免大字体包影响首屏。

布局最大宽度 1200 px，桌面 12 列、小屏单列；间距采用 4/8/12/16/24/32/48/64；圆角 8/12/16。暗色模式维护独立对比度，不只是反转颜色。标题 44-56 px 桌面、30-36 px 移动，正文至少 16 px。具体 tokens 随包提供，最终颜色须实际测试 WCAG 2.2 AA 对比度。[W04]

减少无信息动画。首页 hero 图片固定宽高，视频点击后加载；移动端不下载自动播放的大视频。状态要使用文字与图标，不能只靠颜色。线框图仅规定信息层级，正式视觉应由真实产品内容填充。

## 下载 manifest 与发布一致性

官网读取的发布清单应包括 schema_version、product_version、channel、source_sha、published_at、platform/arch、min_os、asset_url、sha256、size、signature_status、notarization_status、release_notes_url、supported_capabilities 和已知问题。未发布阶段 stable_release 为 null，页面据此禁用正式下载。

官网清单是内容数据，不应直接充当 Tauri updater 签名清单。更新器使用独立受信格式和签名规则。校验值和下载链接必须来自最终发布资产，不能由网页手工填写假 hash。构建失败或清单不全就停止新的站点发布，不影响现有稳定页面。

## 搜索、SEO、可访问性与性能

每页有独立 title/description、canonical、对应语言 hreflang、sitemap 与 robots；预览环境不索引，正式站 canonical 指向真实域名。结构化数据只描述已存在的软件与发行物，未发布版本不填写伪造下载/评分。OG 图片与仓库预览使用同一内容。

键盘可完成导航、语言切换、搜索和下载；提供 skip link、可见焦点、合理标题层级、表格说明、图片 alt 和视频字幕；320 px 宽度及放大文字时不遮挡关键操作。以 WCAG 2.2 AA 为设计目标，并用人工键盘/读屏检查补充自动扫描。[W04]

性能目标为团队自定验收建议：文档页尽量静态、首屏无大体积脚本；以实际移动网络测试 LCP/CLS/交互体验，记录测量环境和优化前后，不在官网显示未经测量的分数。对安装入口、404、搜索无结果、中英文缺页和外链失效做明确处理。默认不加跨站广告追踪；若以后加入统计，应说明采集范围和保留方式。

## 网站验收

每个 CTA 可达；真实下载与 checksum 匹配；语言切换保留同一页面含义；至少 Safari/Chrome 和手机宽度验证；搜索能找到安装、停止、UNKNOWN、Keychain与模型配置；API keys 不进入静态产物；网站缺功能不能通过在文案里宣称支持来补足。
